**Legend:**
* *Complete*: The binary format is fully implemented/documented.
* *Partial*: Enough of the binary format is known to create usable results, but some things are still not known or not implemented.
* *Limited*: Some work has begun, but it's not enough for *Partial*, yet.
* *None*: Nothing about this binary format is known.

| Unit            | [Partial](File%20Type%20-%20Unit.md) | ✓           | ✓             | DTMT compiles a `.unit` (SJSON) plus a `.bsi` (SJSON geometry) into the runtime payload and decompiles a payload back into one, and a static single-mesh unit spawns in game. A shipped sweep (`examples/unit_probe.rs`; 2,666 units in 400 bundles) measures the gap: **168 decode** (skins, animations, streamed meshes and actor/camera/light units are rejected with clear errors) and **168 round-trip byte-for-byte - every decodable shipped unit** (0 before this week's fixes). The dominant loss was the **bounding volumes** - baked at cook time, so recomputing them from the stored half-float vertices always drifted; the geometry's `bounds` are now carried and reused by the geometry, the mesh objects and the LOD union. The scene graph carries the payload's own `index`/`rotation`/`scale`/`world`, and the `.unit` maps are `IndexMap`. The last class was the LOD-object section: its records carry an `unk2` hash, `unk4`/`unk5` and a stream mesh order that the compiler did not model, costing exactly four bytes per unit. Carrying it verbatim closed the sweep. A decompiled geometry carries its record verbatim and the mesh-object render flags are carried too. LOD decompilation is untested. **Updated 2026-10-14:** the 400-bundle sweep reads **508 decoded, 508 byte-identical** (from 168), and the classes that were rejected outright are now carried verbatim - skins, the simple-animation blob and its groups, actors, cameras and lights, and the device blob - because `bitsquid-blender-tools`' `stingray/unit/dt.py` gives every layout and each section is either length-prefixed or fixed-size per record. Two SJSON-reader fixes (a `u64` above `i64::MAX`, and the word `inf`) mean nothing that decodes now fails to round-trip. The classes left are **streamed geometry**, which is *not* a gap - its vertex bytes are in no bundle (3,000 bundles / 19,133 unit entries, no unit variant external), so the guard is deliberate - and one `(9, 8)` channel unit. A fresh 120-bundle sweep (404 units) on the tree that carries actors and cameras reads **130 decoded, 130 byte-identical, 0 rebuilt-but-different, 0 recompile failures**, and its rejection list contains *only* streamed geometry (273) and that one `(9, 8)` unit - i.e. the actor and camera sections no longer appear as rejections at all. |
| Bones           | [Complete](File%20Type%20-%20Bones.-.md) | ✓           | ✓             | The cooked **body** (joint names, their 32-bit ids, the LOD counts) is decoded and compiled (`filetype/bones.rs`); a bundle variant stores the body alone and the community writer's standalone 38-byte envelope is accepted too. All **723 shipped `bones` variants** in 2,500 sampled bundles decode, pass every joint-id check and round-trip byte-for-byte (`examples/bones_probe.rs`). |

| Font (`.slug`)  | Partial       | ✓           | ✓             | Fonts are **`slug`-typed bundle entries** (`A27B4D04A9BA6F9E`, magic `guls`, version `0x0700`), *not* materials: Darktide ships **14** in `packages/boot` (`content/ui/fonts/*` plus `core/performance_hud/debug`) and 8 more in `packages/ui/fonts/slug_{ja,ko,zh_cn,zh_tw}`. `filetype/slug.rs` reads one (header, the four `{tag, base, count}` records, `HLF4` kerning, `16U2` glyph/marker records) and `dtmt build` packs a user-supplied `.slug` **verbatim**, so a **custom font ships today**: the UI resolves fonts by name, so dropping the file at `content/ui/fonts/<name>` and listing it in the package is enough. **Nothing about the font has been verified in game yet, and the earlier "verified in game" claims here were wrong.** The reason was not the engine but the deployment: DTMM had deployed the mod bundle once (10,514 bytes, built *before* the font existed) and every `dtmt build` since only wrote `out/`, so no run ever had a font deployed. Found by comparing the hashes. The built bundle (521,407 bytes, carrying an `a27b4d04a9ba6f9e` entry of 857,520 bytes - a Comic Sans compiled with `slugfont.exe`) is now copied over the deployed one and the game re-run. What *is* established is the bundle level: a `.slug` is packed verbatim under the exact name the UI asks for. Still open: the glyph table is found by a run heuristic that works for the CJK entries (218 glyphs + 221 markers at `92,288`) but not for the Latin fonts, and the `COMP` regions are not decoded. |

The initializer operand fields, the simulator data and the visualizer record bodies are still opaque hex. The community `particles_resource` decodes them. |
