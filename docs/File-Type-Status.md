**Legend:**
* *Complete*: The binary format is fully implemented/documented.
* *Partial*: Enough of the binary format is known to create usable results, but some things are still not known or not implemented.
* *Limited*: Some work has begun, but it's not enough for *Partial*, yet.
* *None*: Nothing about this binary format is known.

| Unit            | [Partial](File%20Type%20-%20Unit.md) | ✓           | ✓             | DTMT compiles a `.unit` (SJSON) plus a `.bsi` (SJSON geometry) into the runtime payload and decompiles a payload back into one, and a static single-mesh unit spawns in game. A shipped sweep (`examples/unit_probe.rs`; 2,666 units in 400 bundles) measures the gap: **168 decode** (skins, animations, streamed meshes and actor/camera/light units are rejected with clear errors) and **168 round-trip byte-for-byte - every decodable shipped unit** (0 before this week's fixes). The dominant loss was the **bounding volumes** - baked at cook time, so recomputing them from the stored half-float vertices always drifted; the geometry's `bounds` are now carried and reused by the geometry, the mesh objects and the LOD union. The scene graph carries the payload's own `index`/`rotation`/`scale`/`world`, and the `.unit` maps are `IndexMap`. The last class was the LOD-object section: its records carry an `unk2` hash, `unk4`/`unk5` and a stream mesh order that the compiler did not model, costing exactly four bytes per unit. Carrying it verbatim closed the sweep. A decompiled geometry carries its record verbatim and the mesh-object render flags are carried too. LOD decompilation is untested. **Updated 2026-10-14:** the 400-bundle sweep reads **508 decoded, 508 byte-identical** (from 168), and the classes that were rejected outright are now carried verbatim - skins, the simple-animation blob and its groups, actors, cameras and lights, and the device blob - because `bitsquid-blender-tools`' `stingray/unit/dt.py` gives every layout and each section is either length-prefixed or fixed-size per record. Two SJSON-reader fixes (a `u64` above `i64::MAX`, and the word `inf`) mean nothing that decodes now fails to round-trip. The classes left are **streamed geometry**, which is *not* a gap - its vertex bytes are in no bundle (3,000 bundles / 19,133 unit entries, no unit variant external), so the guard is deliberate - and one `(9, 8)` channel unit. A fresh 120-bundle sweep (404 units) on the tree that carries actors and cameras reads **130 decoded, 130 byte-identical, 0 rebuilt-but-different, 0 recompile failures**, and its rejection list contains *only* streamed geometry (273) and that one `(9, 8)` unit **Updated 2026-10-14:** that unit now decodes too - channel component 9 with channel type 8 is four signed 16-bit values per element (`SHORT4`, not `HALF4`: read as halves the shipped words give `236.1`), so the decode, the `.bsi` names `NEW_DT`/`CT_SHORT4` and the compile arm are in and the 120-bundle sweep reads **131 decoded / 131 byte-identical**. The only remaining rejections are streamed geometry, which is deliberate. - i.e. the actor and camera sections no longer appear as rejections at all. |

| Font (`.slug`)  | Partial       | ✓           | ✓             | Fonts are **`slug`-typed bundle entries** (`A27B4D04A9BA6F9E`, magic `guls`, version `0x0700`), *not* materials: Darktide ships **14** in `packages/boot` (`content/ui/fonts/*` plus `core/performance_hud/debug`) and 8 more in `packages/ui/fonts/slug_{ja,ko,zh_cn,zh_tw}`. `filetype/slug.rs` reads one (header, the four `{tag, base, count}` records, `HLF4` kerning, `16U2` glyph/marker records) and `dtmt build` packs a user-supplied `.slug` **verbatim**, so a **custom font ships today**: the UI resolves fonts by name, so dropping the file at `content/ui/fonts/<name>` and listing it in the package is enough. **A custom font IS drawn on screen (demonstrated 2026-10-14).** A `slugfont.exe`-compiled Comic Sans shipped under **all 13** `content/ui/fonts/*` names, with the bundle *deployed* (built hash = deployed hash), makes the title screen render `++ Processing Inquisitorial Clearance ++` in Comic Sans - rounded, informal letterforms the game does not ship. So a mod *can* override a font the game loads, including the Latin ones that live in `packages/boot`, and the earlier load-order worry was unfounded. The two real obstacles were a **stale deployment** (DTMM's copy was the pre-font build, so nothing new ever reached the game) and **shadowing a single name** that the visible strings do not use. **Which of the 13: `mono_tide_regular`, established.** A run with *only* that name overridden renders the loading screen (`Blessed is the mind too small for doubt`) in Comic Sans, so a mod needs **one** `.slug` - a 521 KB bundle rather than 6.6 MB - to replace the UI body font, exactly as `boot_ui.lua` claims. The earlier "a single name does not work" note was based on an invalid comparison: the frame it used came from a run with **no font deployed at all**, so nothing could have changed. **The A/B is now same-screen.** With the override removed and the bundle rebuilt (10,512 bytes, 0 `slug` entries) and deployed, the *same* loading screen renders `Burn the heretic! Kill the mutant! Purge the unclean!` in the stock condensed face. So the only variable between the two frames is the `.slug` - no longer a comparison across screens.

**Superseded note, kept for the record:** The "shadowing a single name" note above is weaker than it reads: the unchanged frame that prompted it was the *operative menu*, while the demonstration frame is the *title/loading* screen - and the title screen was never checked with only `mono_tide_regular` overridden, which `boot_ui.lua` names as the UI default. So the honest claim is "all 13 works; one unknown name may well also work". A single run with that name overridden, looking at the *title* screen rather than the menu, settles it; bisecting the 13 would take about four. The refinement is to narrow to the names actually in use - the UI font table, `scripts/managers/ui/ui_fonts` - and the bundle-level fact stands: a `.slug` is packed verbatim under the exact name asked for, byte-identical. |
