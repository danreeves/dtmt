**Legend:**
* *Complete*: The binary format is fully implemented/documented.
* *Partial*: Enough of the binary format is known to create usable results, but some things are still not known or not implemented.
* *Limited*: Some work has begun, but it's not enough for *Partial*, yet.
* *None*: Nothing about this binary format is known.

| Texture         | [Partial](File%20Type%20-%20Texture.-.md) | ✓ | ✓ | Wrapper, texture header and DDS layouts are known and verified against shipped data. Known gaps: the game's side-file names and streamed name-slot length are not reproduced exactly when compiling (see the doc). A few `flags` bits and the full set of `category` values are still unverified.
| Material | [Partial](File%20Type%20-%20Material.-.md) | ✓           | ✓             | Instance and base materials compile and round trip byte-for-byte. Base materials can carry custom shaders compiled from HLSL with `dxc` **as long as the shader interface is a shipped one**: our own programs, textures through the library's channels, and values for the library's known variables (bound by name) all work in game. Renaming a library variable works (verified in game); adding variables (cloned records) and renaming channels are deployed/implemented and awaiting in-game observation. New channels and our own cbuffers are still blocked on the device block's record grammar (`Shader RE TODO.md`, "Next action"). `unk2`/`unk3` are preserved but not understood, and the shader43 wrapper (contexts, conditions, group data, program reflection tails, default data) is decoded well enough to patch but not yet to generate. |
| Strings         | [Partial](File%20Type%20-%20Strings.-.md)       | ✓           | ✓             | The file format itself is done, but the interaction with bundle properties and file variants is not properly implemented, yet. See https://git.sclu1034.dev/bitsquid_dt/dtmt/issues/3.
| Sound (Wwise)   | Limited          | ✗           | ✗             | Wwise does the heavy lifting anyways, so we "only" need to figure out the version and the post-processing. | Unit            | [Partial](File%20Type%20-%20Unit.md) | ✓           | ✓             | DTMT compiles a `.unit` (SJSON) plus a `.bsi` (SJSON geometry) into the runtime payload and decompiles a payload back into one, and a static single-mesh unit spawns in game. A shipped sweep (`examples/unit_probe.rs`; 2,666 units in 400 bundles) measures the gap: **78 decode** (skins, animations, streamed meshes and actor/camera/light units are rejected with clear errors) and **47 round-trip byte-for-byte** (0 before this week's fixes). The dominant loss was the **bounding volumes** - baked at cook time, so recomputing them from the stored half-float vertices always drifted; the geometry's `bounds` are now carried and reused by the geometry, the mesh objects and the LOD union. The scene graph carries the payload's own `index`/`rotation`/`scale`/`world`, and the `.unit` maps are `IndexMap`. The remaining 31 differ later: another eight-byte field after the material list, and one unit is four bytes longer than shipped. A decompiled geometry carries its record verbatim and the mesh-object render flags are carried too. LOD decompilation is untested. |
| Bones           | [Complete](File%20Type%20-%20Bones.-.md) | ✓           | ✓             | The cooked **body** (joint names, their 32-bit ids, the LOD counts) is decoded and compiled (`filetype/bones.rs`); a bundle variant stores the body alone and the community writer's standalone 38-byte envelope is accepted too. All **723 shipped `bones` variants** in 2,500 sampled bundles decode, pass every joint-id check and round-trip byte-for-byte (`examples/bones_probe.rs`). |
| Level           | None          | ✗           | ✗             |
| Font (`.slug`)  | None          | ✗           | ✗             | A Darktide font is a **material in the `.slug` format** (no `font`/`slug`/`slug_album` bundle entry ships in ~1,700 sampled bundles). Custom fonts need `slug` support: decode the atlas texture reference, glyph metrics and slug parameters from a shipped UI font's material, and compile one back. |
| Particles       | [Limited](File%20Type%20-%20Particles.-.md) | ✓           | ✓             | The effect header, the variables, each system header, the initializer list, the simulator list (op names + offsets) and the visualizer list (types) are decoded and compiled (`filetype/particles.rs`); six shipped effects round-trip byte-for-byte. The initializer operand fields, the simulator data and the visualizer record bodies are still opaque hex. The community `particles_resource` decodes them. |

Anything not mentioned explicitly is to be considered unknown.
